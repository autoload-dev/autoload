# Public documentation

These guides explain supported consumer behavior. Start with outcomes and usage, then explain
mechanics needed to use the feature correctly. Describe the present, not release history or
a roadmap. Root/example READMEs have the same audience.

For project/test layout, link to the relevant [layout section](project-layout.md), not to
agent instructions.

In READMEs and getting-started guides, use numbered steps ending in visible success. Preserve
copyable setup and usage for each supported workflow when reorganizing pages. Ruleset fixture
commands belong in [maintainer recipes](../../../docs/internal/verification-recipes.md#regression-fixtures).
