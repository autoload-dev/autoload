## 1. Which files a 4.7.2 web export writes, their names, and their inputs

### Takeaway
Every output file is named `<base>.<suffix>` where `<base>` is the exported HTML file's basename; the exporter extracts *all* template members (renaming `godot` → `<base>`), writes the PCK and GDExtension side modules, overwrites `<base>.html` with the filled shell, always writes the splash `<base>.png`, writes two icons when `html/export_icon` (default `true`), and with `progressive_web_app/enabled` additionally keeps the service worker and offline page and writes `<base>.manifest.json` plus three PWA icons. The prototype's output is therefore missing files a default Godot export has (`.icon.png`, `.apple-touch-icon.png`) and uses a fixed default splash.

### Inferences
- A default 4.7.2 export (no PWA, export_icon on) of base `index` writes 9 files for the nothreads/no-dlink template: `index.html .js .wasm .audio.worklet.js .audio.position.worklet.js .pck .png .icon.png .apple-touch-icon.png`; dlink adds `index.side.wasm` + each extension's `.wasm`; PWA adds 6 files (service worker, offline page, manifest, 3 icons).
- Only `B.html`, `B.png`, the icons and the PWA files depend on project data; `B.js/.wasm/.worklets/.side.wasm` are pure template copies and could be symlinked/copied straight from the runtime in Bazel (cacheable independently of the project). `B.html` depends on the PCK size, so it must be regenerated whenever the pack changes.
- The prototype's `threads = "godot.worker.js" in members` can never be true for 4.7.2/4.8 templates (no such member); Godot decides `$GODOT_THREADS_ENABLED` from the `variant/thread_support` export option, not from the template.
- The service worker's `___GODOT_VERSION___` is `unix_time|ticks_usec` at export time, i.e. intentionally non-deterministic; a hermetic Bazel action needs a deterministic substitute (e.g. a content hash of the cached files) to stay reproducible while still busting the cache on change.

### Gaps
- Whether `<lib>.wasm` names can collide with `B.*` names was not examined; GDExtension web export plugin internals (how `web.wasm32` entries become `SharedObject`s) were not read in this pass.

## 2. How the shell is filled: `$GODOT_*` placeholders, config, splash, icons, PWA manifest, service worker, offline page, custom shell

### Takeaway
`_fix_html` builds a JSON config with exactly ten keys (plus `serviceWorker` under PWA), prepends icon/manifest `<link>`s to `html/head_include`, and substitutes eight `$GODOT_*` placeholders line by line in insertion order. The splash and project icon are written unscaled from their source images; only the apple-touch icon (180×180) and the PWA icons (144/180/512, only if the source differs) are resized with bilinear filtering. Several details differ from the prototype (pool sizes, `fullsize` source, default bg color, icon links).

### Inferences
- Differences between the prototype (`package_web.py`) and 4.7.2 that a reimplementation must close:
  1. Config lacks `godotPoolSize` and `emscriptenPoolSize` (Godot always writes them; runtime defaults are 4 and 8, so the omission is only behaviour-neutral while the options stay at defaults).
  2. `fullsize--` must derive from `application/boot_splash/stretch_mode != 0`, not from `application/boot_splash/fullsize` (a Godot 4.x-earlier setting no longer read in 4.7.2's `_fix_html`).
  3. Threads flag must come from `variant/thread_support`, not template membership.
  4. With `html/export_icon` true (the default) Godot injects two `<link>` tags before the user's head include and writes two icon files; the prototype rejects the option instead.
  5. The fallback bg color when the facts don't carry `application/boot_splash/bg_color` must be `#242424` (0.14×255 = 35.7 → 36), not `#000000` — unless the facts always include defaults.
  6. Python's `round()` is banker's rounding and works on float64; Godot rounds half away from zero on float32. Exact-.5 channel values can differ by one; a `math.floor(v*255+0.5)` on a float32-rounded value would match.
  7. Godot appends `\n` after each line (one extra trailing newline) and replaces per line in insertion order; values are not escaped (a project name with `<` or `$GODOT_CONFIG` passes through / gets substituted). Byte-identical output requires the same order and line handling.
- Because the splash and icon are just the project's source images re-encoded as PNG (no scaling, except apple-touch 180 and PWA icons), the shell probe only needs to record *which* image files and their decoded pixels; rendering via the probe (as for iOS/Android) matches Godot exactly, including SVG rasterization and `.import`-based decompression. A pure-Python path would need to handle any `ResourceLoader` texture type, which argues for the probe.
- `html/custom_html_shell` and `progressive_web_app/offline_page` and `progressive_web_app/icon_*` are all `res://` project files; they can be resolved from the pack's sources the same way the ruleset resolves `application/liquid_glass_icon`. The offline page is copied verbatim; the custom shell goes through the same substitution.
- `serviceWorker` in the config both triggers registration after start and enables the COI-reload path in the default shell; it is set only when PWA is enabled. So "cross-origin isolation without server headers" (needed for threads/hosts like GitHub Pages) requires the PWA files.

### Gaps
- `DefaultProjectIcon`'s exact raster size during a headless export (EDSCALE in `--headless --export-*`) was not verified by running an export.
- Whether the shell probe currently records project-setting defaults (e.g. `bg_color`, `stretch_mode`) when they are absent from `project.godot` was not checked.

## 3. Debug vs release differences

### Takeaway
For a normal (CLI or dialog) export, debug vs release differs only in the template chosen (`web*_debug.zip` vs `*_release.zip`) and the pack's debug features; `args` stays `[]` because those exports pass no debug flags. Remote-debug/breakpoint args are only added by the editor's one-click "Run in Browser".

### Cited Findings

## 4. Identifying the runtime/template version (for an engine-version check)

### Takeaway
The Godot version is not in `godot.js`; it is a plain string `Godot Engine v<version>.official` (plus the commit hash) inside the engine wasm — `godot.wasm` for non-dlink templates, `godot.side.wasm` for dlink templates. `godot.js` instead embeds the Emscripten version (`4.0.20` in 4.7.2, `6.0.12` in 4.8.beta1), which is what GDExtension side modules must match.

### Cited Findings
- `strings` on 4.7.2 `godot.wasm` (nothreads release and debug) yields `Godot Engine v4.7.2.stable.official` and the 40-hex commit `ed1daf0bf001b61586d9930840f2f1394092c079`; on 4.8.beta1 `godot.wasm` yields `Godot Engine v4.8.beta1.official`; on the 4.7.2 dlink template the string is in `godot.side.wasm`, not in the 1.6 MB main `godot.wasm` — local `strings` runs on extracted [T47](file://T47) / [T48](file://T48) templates
- `godot.js` contains no Godot version string, but `godot_js_emscripten_get_version` returns `GodotRuntime.allocString('{{{ EMSCRIPTEN_VERSION }}}')`, which resolves to `"4.0.20"` in all checked 4.7.2 templates (nothreads release/debug, threads release, dlink debug) and `"6.0.12"` in 4.8.beta1 — [G47/platform/web/js/libs/library_godot_emscripten.js:35-41](file://G47/platform/web/js/libs/library_godot_emscripten.js); `grep` on extracted templates
- 4.8 raises the minimum Emscripten to 6.0.1 (dlink+threads requires 6.0.12); 4.7.2 required ≥ 4.0.0 — [G48/platform/web/detect.py](file://G48/platform/web/detect.py) vs [G47/platform/web/detect.py:117-118](file://G47/platform/web/detect.py)
- The editor-build service worker gets `___GODOT_VERSION___ = get_build_version(False)` at build time, but the export template's service worker is shipped unsubstituted — [G47/platform/web/emscripten_helpers.py:69-77, 106-107](file://G47/platform/web/emscripten_helpers.py)

### Inferences
- An engine-version check for web runtimes can scan the (side) wasm for the `Godot Engine v` prefix — analogous to scanning native binaries — and select the file by template kind (`godot.side.wasm` if present, else `godot.wasm`). Scanning ~40 MB is cheap compared to extraction. Alternatively compare the template ZIP's hash against a pinned profile, as the archive is already pinned.
- The Emscripten version in `godot.js` is a natural, cheap fact for validating that GDExtension side modules were built with the matching emsdk (relevant to decision 2).

### Gaps
- Not checked whether custom (source-built) templates without `.official` build name keep the same `Godot Engine v` prefix format (they should, via `VERSION_FULL_BUILD`, but not verified).

## 5. Hosting requirements and conventions

### Takeaway
A nothreads, non-dlink export runs on any static HTTPS host with no special headers; threads (and, per Godot docs, extensions) need COOP/COEP or Godot's PWA service-worker workaround. itch.io wants an `index.html` in a ZIP (≤1,000 files, ≤500 MB, ≤200 MB per file) and has an opt-in SharedArrayBuffer toggle; Cloudflare Pages' 25 MiB per-file limit is smaller than Godot's ~38–40 MB `godot.wasm`, so uncompressed Godot exports do not deploy there as is. Godot's loader forces `application/wasm` itself and relies on transparent HTTP `Content-Encoding`, so pre-compression is a hosting concern, not a loader feature.

### Cited Findings
- Godot docs (4.7): `index.html` naming suggested; renaming other exported files can cause issues; `.wasm` should be `application/wasm` "otherwise some start-up optimizations are lost"; `.pck` usually `application/octet-stream`; HTTPS needed for some features (localhost exempt); threads need `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`; serve `.pck`/`.wasm` compressed, wasm gzips to ~¼, Brotli precompression recommended; GitHub Pages compresses on the fly, itch.io does not, GitLab Pages supports manual gzip precompression; single-threaded export (default since 4.3) is more compatible with itch.io, Poki, CrazyGames; Extensions Support "also need[s] cross-origin isolation headers"; only the Compatibility renderer works; C# cannot export to web — [Exporting for the Web (4.7 docs)](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)
- Godot's loader re-wraps the fetched wasm response with `content-type: application/wasm` before `WebAssembly.instantiateStreaming`, falling back to `arrayBuffer()` + `instantiate` — [G47/platform/web/js/engine/engine.js `doInit`](file://G47/platform/web/js/engine/engine.js); [G47/platform/web/js/engine/config.js:294-307](file://G47/platform/web/js/engine/config.js)
- Loader fetches plain `B.wasm` / `B.pck` URLs (no `.br`/`.gz` variants); progress counts bytes read from the response body stream against `fileSizes` (uncompressed sizes), with 4 download attempts — [G47/platform/web/js/engine/preloader.js:29-105](file://G47/platform/web/js/engine/preloader.js)
- itch.io: ZIP must contain `index.html`; case-sensitive UTF-8 names; relative paths only; ≤1,000 files, ≤240-char paths, ≤500 MB extracted total, ≤200 MB per file; ZIP only; pre-compressed gzip detected by content, Brotli by `.br` extension (content-type from the name without `.br`/`.gz`); automatic gzip by extension includes `html js css svg wasm wav glb pck`; embed vs click-to-launch fullscreen, "Mobile Friendly" option — [itch.io HTML5 docs](https://itch.io/docs/creators/html5). (Contradiction: Godot docs say itch.io "does not provide on-the-fly compression", the itch.io docs list automatic gzip for `wasm`/`pck`; the itch.io page is the primary source.)
- itch.io SharedArrayBuffer: opt-in "SharedArrayBuffer support" checkbox under Embed Options → Frame Options; files on `html.itch.zone`; HTML on CDN gets COOP `same-origin`, COEP `require-corp`, CORP `cross-origin`; the game page gets COEP `credentialless`; third-party iframes (YouTube etc.) break; Safari still needs a popup window; Firefox origin-trial token expired end of 2023, later popup removed (announced 2 Apr 2022, updated since) — [itch.io forum: Experimental SharedArrayBuffer support](https://itch.io/t/2025776/experimental-sharedarraybuffer-support)
- GitHub Pages: 1 GB published site, 100 GB/month soft bandwidth, 10-minute deployment timeout; no documented custom headers — [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits); the COOP/COEP feature request remains open with no timeline, `coi-serviceworker` is the common workaround — [GitHub community discussion #13309](https://github.com/orgs/community/discussions/13309)
- Netlify: `_headers` file in the publish directory (path line, indented headers) or `[[headers]]` in `netlify.toml`; `Content-Encoding` and `Content-Length` are managed by Netlify and ignored if set — [Netlify custom headers](https://docs.netlify.com/manage/routing/headers/)
- Cloudflare Pages: max 25 MiB per asset; 20,000 files (Free); `_headers` max 100 rules, 2,000 chars per header; larger files → R2 — [Cloudflare Pages limits](https://developers.cloudflare.com/pages/platform/limits/)
- CrazyGames: ≤250 MB total, ≤1,500 files, initial download ≤50 MB (≤20 MB for mobile homepage; without SDK total size counts, ceiling 50 MB); relative paths only — [CrazyGames technical requirements](https://docs.crazygames.com/requirements/technical/)
- Godot's own dev server sends `Cache-Control: no-store, max-age=0` (no caching policy for production is shipped) — [editor_http_server.cpp:112-114](file://G47/platform/web/export/editor_http_server.cpp)

### Inferences
- `index.*` naming (prototype decision 6) matches itch.io, GitHub Pages and generic static hosting; a name that follows the app's name would need an extra `index.html` for itch.io.
- Uncompressed 4.7.2 exports exceed Cloudflare Pages' 25 MiB asset limit (godot.wasm 37.9–39.5 MB, side.wasm 42.6 MB) and CrazyGames' 20 MB mobile initial-download target even before the PCK; pre-compression doesn't help Cloudflare Pages since the limit is per stored asset and Pages has no documented `Content-Encoding` override (not verified). This is a reason to offer pre-compressed variants (`.br`/`.gz`) as optional output for hosts that support them (itch.io `.br` detection, nginx `gzip_static`/`brotli_static`), while keeping uncompressed files as the canonical output since Godot's loader never requests `.br`/`.gz` URLs.
- `fileSizes` must stay uncompressed sizes: the stream reader sees decoded bytes.
- Because the service worker caches by fixed URL and uses a version string to bust caches, and the non-PWA export has no hashed file names, long `Cache-Control: immutable` caching is unsafe for `index.*` files unless the deploy changes URLs; a short/no-cache policy on `index.html`/`.pck` is the safe default.
- A `_headers` file (Netlify/Cloudflare) with COOP/COEP is the server-side counterpart of the PWA workaround for threads builds; it could be an optional generated file.

### Gaps
- Poki and Newgrounds requirements were not researched (Godot docs only mention Poki compatibility for single-threaded exports).
- No authoritative current statement that GitHub Pages lacks custom headers (only absence from docs plus the open feature request).
- Cloudflare Pages `_headers` syntax and pre-compressed asset handling not fetched.

## 6. Debug symbols for wasm

### Takeaway
Official Godot web templates ship with no debug information at all (no name section, no DWARF, no source map). Godot's build only offers embedded DWARF (`debug_symbols=yes` → `-g3 -gdwarf-4`) plus `--profiling-funcs`; it has no separate-debug-file support for web. Emscripten itself offers `-gsource-map`, `-gseparate-dwarf[=FILE]` (with a URL embedded for DevTools), `--profiling-funcs`/`-g2` name sections, and `emsymbolizer`; Chrome debugs DWARF via the "C/C++ DevTools Support (DWARF)" extension.

### Cited Findings
- Custom-section scan (own parser) of 4.7.2 `godot.wasm` (nothreads release and debug) and 4.8.beta1 `godot.wasm`: no custom sections; 4.7.2 dlink `godot.wasm`/`godot.side.wasm`: only `dylink.0` — local scan of extracted [T47](file://T47) / [T48](file://T48) templates; no `sourceMappingURL` in `godot.js`
- Godot SCons: with `debug_symbols`, Emscripten builds add `-gdwarf-4 -g3` to compile and link flags ("Emscripten only produces dwarf symbols when using -g3") — [G47/SConstruct:855-870](file://G47/SConstruct); web additionally links `--profiling-funcs` ("Retain function names for backtraces") — [G47/platform/web/detect.py:154-156](file://G47/platform/web/detect.py); `separate_debug_symbols` is a global option but `platform/web` never references it — [G47/SConstruct:178-179](file://G47/SConstruct), `grep` of `G47/platform/web`
- Emscripten: `-g3` (= `-g`) keeps DWARF after linking; `-g2` adds a name section cheaply; `-gsource-map` emits `program.wasm.map` from DWARF and survives full optimization (no DWARF in output unless `-g` too); `-gseparate-dwarf` writes debug info to a separate file; alternatively strip with `llvm-strip` and keep the unstripped copy for symbolication; `-gline-tables-only` reduces size; `emsymbolizer` maps addresses using DWARF, source maps, symbol maps (`--emit-symbol-map`), name sections; DWARF "can be large" and limits some Binaryen optimizations — [Emscripten: Debugging](https://emscripten.org/docs/porting/Debugging.html)
- `-gseparate-dwarf=<file>`: the main wasm then contains a URL to the debug file so DevTools can find it; `SEPARATE_DWARF_URL` overrides that URL (e.g. different server); Chrome needs the "C/C++ DevTools Support (DWARF)" extension, with path mapping in its options for builds made elsewhere — [Chrome DevTools: Debug C/C++ WebAssembly](https://developer.chrome.com/docs/devtools/wasm) (via search summary); [Emscripten emcc reference (Debian mirror)](https://sources.debian.org/src/emscripten/3.1.69%2Bdfsg-4/site/source/docs/tools_reference/emcc.rst)

### Inferences
- For prebuilt runtimes, rules_godot has nothing to collect: the web backend returning no debug symbols is correct.
- For a future source-built web engine (decision 2), the idiomatic counterpart of `.dSYM`/`.debug` is `-gseparate-dwarf=godot.debug.wasm` (+ `SEPARATE_DWARF_URL` if hosted elsewhere) or a `-gsource-map` `.wasm.map`, kept out of the deployable directory; `--profiling-funcs` (name section) is the cheap middle ground that makes browser stack traces readable. Godot's SCons doesn't do this out of the box, so the SCons translation would have to add it.

### Gaps
- Exact current semantics of `-gseparate-dwarf` and `SEPARATE_DWARF_URL` were taken from a search summary, not a full page read; whether Firefox/Safari consume DWARF was not researched.

## 7. Godot 4.8 beta differences relevant to the web exporter

### Takeaway
The web exporter, the HTML shell, the service worker and the template layout are unchanged between 4.7.2 and 4.8 beta for exports; differences are build-side (Emscripten ≥ 6.0.1, wasm64 dropped, `-fwasm-exceptions` for dlink) and editor-side (web editor debugger over MessagePort).
