# Operation Catalogue

See [artifact IDs](artifacts.md), [dependency edges](dependencies.md) and [evidence](evidence.md).
These are semantic phases; a single Godot invocation may perform several, and a ruleset
operation may invoke Godot several times. No operation name here proposes a new public rule.
D/C denotes direct/conditional reads. All actions additionally read their actual tool code,
arguments/manifests and execution-platform inputs.

## Validation and source execution

| ID / operation | Inputs | Outputs and side effects | Current ownership and evidence |
|---|---|---|---|
| OP-CHECK: check declared GDScripts | D source runtime environment, LAUNCH checker/cases/options, warning policy and ENGINE; C relevant autoload/preload/static initialization, extension runtime library code and EXTERNAL | In-memory parse/analysis/compilation/static state, per-script REPORT/JUnit and exit status | The per-unit [content validation](../../../rules_godot/tools/validation/validate.gd) loads a unit's scripts and then its scenes with ResourceLoader.load in the editor, under the project's warning settings, with stub autoloads and without tool annotations, so no project code runs; it is not upstream --check-only. | OP-GDUNIT: discover/select/run suites | D source environment, pinned framework/bootstrap/own candidate .gd roots, helper/suite closure, LAUNCH filter/shard/report policy; C autoloads/extension libraries/runtime state | Framework reports/JUnit/exit and arbitrary suite writes under declared/external contract | GdUnit validates inheritance/global class data. | OP-RUN-SOURCE: source run of a script or scene | D runtime PURPOSE-CONFIG, selected SOURCE/import/global metadata/EXT-LIST, ENGINE, LAUNCH; C autoloads, EXT-LIBS, RENDER-CACHE/EXTERNAL and delivered pack bytes | Runtime behavior/reports/saves, updated process/cache/user state | Current runner consumes full project.files/imports/INITIALIZED and normalizes ordinary data roots. --script bypasses main scene, not autoload/static/plugin dependencies. F/R [S03](evidence.md#s03), [R04](evidence.md#r04) |

## Export, packaging and delivered execution

| ID / operation | Inputs | Outputs and side effects | Current ownership and evidence |
|---|---|---|---|
| OP-SELECT: choose pack membership and prerequisite availability | D declared resource graph/explicit roots, exclusions/optional/extension library paths, PROJECT; C prior pack identity SELECTION metadata | SELECTION/content manifest/report; resources attributed to required packs can be omitted | GodotPackSelection or analysis-written all-content manifest. Required metadata is not a mounted/delivered pack and not upstream patch bytes. R [R01](evidence.md#r01), [R06](evidence.md#r06) |
| OP-PCK: export resource pack | D ENGINE/exporter, export PURPOSE-CONFIG, PRESET/FEATURES, SOURCE/sidecars/IMPORTED, SELECTION; C export/import PLUGIN/EXT-LIBS, exporter-generated metadata, EXPORT-CACHE, CREDENTIALS, shader compiler/backend/RENDER-CACHE, true prior PCK bytes in upstream patch mode | PCK and exported/remapped/filtered EXPORTED resources/metadata; wrapper REPORT; scratch/customization caches; upstream optional shared-object collection when requested | GodotPack declares full project.files/imports and runs --export-pack, whose own scan imports what the staged imports lack. It does not directly consume current project.INITIALIZED; its rescan derives metadata. F/R [S08](evidence.md#s08), [S10](evidence.md#s10), [S12](evidence.md#s12), [R02](evidence.md#r02) |
| OP-SHELL: report export facts and generate shell assets | D same export setup/current project resources/imports, injected probe PLUGIN, engine default images/profile; C requested Android/Apple image tools | EXPORT-FACTS, SHELL-ASSETS and discarded scratch probe PCK/logs | GodotShellAssets is another lazy export, not a read of main PCK output or a universal Godot phase. It stages the project without game-only scripts and scenes, keeping those of enabled import/export plugins and autoloads with their dependencies. R [R08](evidence.md#r08) |
| OP-APPLICATION: build/link/package an application | D RUNTIME, PCK, runtime EXT-LIBS/PLATFORM-LIBS, target platform/ABI/feature tags/options/TOOLS; C EXPORT-FACTS, SHELL-ASSETS/FILES, extra resources and signing mode | APPLICATION, generated shell/bootstrap files, compiled/linked products and conditional SYMBOLS/SIGNED | Existing desktop/Android/iOS application backends delegate to rules_cc/rules_android/rules_apple providers, aspects and toolchains. Extension library delivery/linkage is separate from PCK resource storage. R [R05](evidence.md#r05) |
| OP-SYMBOLS: preserve symbols and strip packaged copies | D native unstripped/object/link outputs, tools and flags; C existing dSYM/link maps | SYMBOLS, stripped native packaged copies and preserved ID/UUID association | Existing symbols/native tools; symbols can be lazy output groups/companion targets. Stripping may renew adhoc signature but does not imply full app signing. R [R05](evidence.md#r05) |
| OP-SIGN: sign/verify an application | D unsigned application/package, SIGNING policy/material refs/TOOLS; C external keychain/provisioning/service state | SIGNED copy/archive/package and verification status | macOS certificate signing is local/noncacheable; adhoc differs. Android/iOS signing participates in delegated packaging. Not notarization. R [R05](evidence.md#r05) |
| OP-MOUNT: mount an additional resource pack | D actual PCK bytes, process PACK-STATE/load order/replace_files/offset; C included class/UID cache entries | Mutated virtual lookup/class/UID state; existing objects/cache can retain prior state | Project code explicitly calls load_resource_pack; no implicit project-settings/autoload/extension activation. Different from physically copying a PCK. F [S02](evidence.md#s02), [S05](evidence.md#s05), [S09](evidence.md#s09) |
| OP-RUN-PACK: start exported content or packaged application | D main PCK, ENGINE (runner) or RUNTIME/APPLICATION, LAUNCH/config/extension library requirements; C explicitly delivered extra packs, PACK-STATE/EXTERNAL/RENDER-CACHE | Execution REPORT/behavior/saves and process state; explicit OP-MOUNT may follow | Current runner stages extension library resource paths only from the main pack's project plus extra PCK bytes. Applications have operating-system-specific native linkage/staging. F/R [S03](evidence.md#s03), [S09](evidence.md#s09), [R04](evidence.md#r04), [R05](evidence.md#r05) |

Input cells omit the common ART- prefix for readability. They identify semantic dependencies,
not a claim every facility is exposed by today's rules. Encrypted export, upstream delta
export, external importer setup and shader baking have explicit support/verification limits
in [evidence](evidence.md#open-questions-and-coverage-limits).

## Application packaging per operating system

| Operating system | Application packaging | Execution/tool dependency boundary |
|---|---|---|
| Linux | Runtime + PCK + physical extension/dependent libraries → executable tree/archive/launcher | C++ toolchain/symbol tools and actual runtime operating-system loading |
| macOS | App metadata/icons/resources + runtime/PCK/physical libraries → unsigned bundle/archive, optional signed copy | Apple tools, symbol UUIDs, deployment settings and signing mode/keychain |
| Android | Java/AAR/resources/manifests + engine library and per-ABI extension libraries + PCK assets → APK/AAB | Java/SDK/NDK/rules_android ABI/resource/symbol/signing graph |
| iOS | Static engine library/extension libraries/compiled dependency providers + startup registration + resources/PCK/plists → linked app/IPA | Xcode/SDK/CPU/iOS environment/Swift/framework/signing and dSYM graph |

Extension editor libraries remain separate from these extension runtime libraries. SDKs
affect the operations that actually use them, not every resource operation merely because
a mobile artifact will eventually be built. [R05](evidence.md#r05), [R07](evidence.md#r07)
